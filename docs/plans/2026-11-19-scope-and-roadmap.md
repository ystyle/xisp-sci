## 1. 本仓的定位

**本仓是 xisp 的计算引擎层扩展，不是计算平台。**

一句话判据：*这个功能是在「算数」，还是在「展示、编排、存储」？* 只有前者进本仓。

所以本仓的产出永远是 **Lisp 侧可调用的计算能力**（`External` 值 + 注册符号 + 能力域），
不产出界面、协议、存储格式。前端要画图，读本仓输出的结构化数据自己画。

## 2. 最终范围：7 个模块

### 2.1 成员清单

| 模块 | 职责 | 依赖 | 对应的平台模块 |
|---|---|---|---|
| `xisp_array` | **唯一地基**：dtype / shape / strides / 广播 / 视图 / 基础归约 | core | 模块1 |
| `xisp_num` | 数值方法：插值、拟合、优化、ODE、数值积分 | array | 模块5 |
| `xisp_stats` | 统计：描述统计、分位数、相关协方差、直方图、假设检验、回归 | array | 模块3 |
| `xisp_linalg` | 线性代数：matmul / 解方程 / det / inv / 分解 / 特征值 | array | 模块4 |
| `xisp_signal` | 信号处理：fft / ifft / 卷积 / 滤波 / 窗函数 | array | 模块6 |
| `xisp_io` | 数据 IO：CSV、二进制、交换格式（JSON 复用 `xisp_json`） | array | 模块7 |
| `xisp_sci` | **门面**：聚合 re-export + 跨域工作流，不含重实现 | 上面全部 | — |

### 2.2 依赖规则（严格单向）

```
        xisp（core：LispValue / External 协议 / 域装配 / 中断接缝）
              ↑
        xisp_array            ← 唯一地基
        ↑    ↑    ↑    ↑
   xisp_io  xisp_linalg  xisp_stats  xisp_signal  xisp_num
        ↑    ↑    ↑    ↑    ↑
                xisp_sci           ← 门面：聚合 + 高层 API
```

1. **只有 `xisp_array` 可以被同族其它模块依赖**；
2. `io` / `linalg` / `stats` / `signal` / `num` **互相不得依赖**；
3. `xisp_sci` 只做聚合与跨域工作流，不重复实现；
4. 全族**不得反向依赖** core 以外的语言本体设施（`repl` / `cli` / `xisp_bc`）。

违反任一条都不是风格问题：族内互依会让「只想用统计」的宿主被迫拉进 FFT 和 C 工具链。

### 2.3 不属于本仓

| 平台模块 | 归属 | 判据 |
|---|---|---|
| 模块8 绘图引擎（plot / scatter / 3D / 导出 PNG/SVG） | 前端（cjxt）或独立仓 | 是「展示」不是「算数」。本仓最多提供**图表描述的结构化输出**，渲染不归这里 |
| 模块9 工作空间与数据管理 | 应用层（tsdb / badger-storm） | 是「存储」 |
| 模块10 AI 编排层 | `atelier`（已是独立仓） | 是「编排」 |

### 2.4 边界判据（新增功能时逐条过）

1. **是计算还是展示 / 编排 / 存储？** 后者不进本仓。
2. **需要数组吗？** 不需要、且也不是数值算法的 → 可能该进 core 或独立能力域（例如标量数学，见 §4.1）。
3. **引入外部 C 库吗？** 引入了 → 必须单独成员，并在 `scripts/check-members.sh` 的
   `NATIVE_ALLOWED` 里登记。`[ffi.c]` / `link-option` **不随 workspace 根生效**，每个成员要各自声明。
4. **落在哪个族？** 按 §2.2 单向依赖放到唯一合适的模块。放不进去说明划分有问题，
   先改本文再写代码。
5. **它会引入大量顶层符号吗？** 会 → 符号必须写进 `LispCapability.symbols`（沙箱审计 /
   文档生成 / 重名检出的唯一来源）。

## 3. 与 xisp 的版本关系

跨 workspace 依赖**只能走中心仓的精确版本号**（`"ystyle::xisp" = "x.y.z"`），
不能用 `{ path = ... }` —— path 依赖发布不了。

于是有一条硬约束：**xisp 侧加了新 API，本仓要等那个版本发到中心仓才能用上**。

这不是缺陷，是一道检查：**如果发现必须改 xisp 才能实现某个数组能力，多半说明 core 的
`External` 接缝不够用**。那是比「跨仓发版麻烦」重要得多的信号，应当先修接缝，而不是在本仓里绕。

## 4. core 侧的缺口（本仓的阻塞项）

写在这里是因为它们**不是本仓能修的**，但决定了本仓能走到哪一步。

### 4.1 缺口 1：core 没有数学函数

`core/src/core/builtin/domains.cj` 的 `arithmetic` 域，全部内建只有：

```
+  -  *  /  mod  round  min  max  sum  product
```

`sin` / `cos` / `tan` / `asin` / `acos` / `atan` / `exp` / `log` / `log10` / `sqrt` / `cbrt` /
`pow` / `hypot` / `abs` / `floor` / `ceil` / `sign` / `gamma` / `erf` —— **一个都没有**。

**决定：标量版进 core，不进本仓。**

> `(sin 1.0)` 是语言能力，`(sin arr)` 是数组能力。**两者同名，靠能力接口分派** ——
> 不搞 `sin` 与 `array-sin` 两套名字。

理由：标量数学放进 sci 仓，意味着宿主连 `(sin x)` 都要先装一个计算域，荒谬；
而且它会让「只想要数学函数的宿主」被迫依赖 NDArray。

同时这里有一条要守住的纪律（`domains.cj:38` 那条注释记着教训）：**域声明的 `symbols`
是对外契约**，曾经 `abs` 被声明却从未实现，上层以为可用。新加符号必须同时有实现和清单。

### 4.2 缺口 2：core 通用内建对 `External` 的分派不完整

现状：

| 已接通 | 位置 |
|---|---|
| `=` `!=` | `comparison.cj` → `LispExternalEquatable` |
| `<` `>` `<=` `>=` | `comparison.cj` → `LispExternalComparable` |
| `length` `nth` | `list.cj` → `LispExternalIndexable` |
| 调用形式 | `LispExternalCallable` |

| **未接通** | 位置 | 现象 |
|---|---|---|
| `+` `-` `*` `/` | `arithmetic.cj:24` 起，只匹配 `Int` / `Float` | `(+ arr arr)` 报类型错 |
| `sum` `max` `min` `product` | `higher_order.cj:34`，只认 `Cons` 链 | `(sum arr)` 得到 `0.0` 而不是求和 |

`sci-family` 文档 §7.2 的论断——「一等公民待遇来自能力接口分派，不来自专用变体」——
方向是对的，但目前**只做了一半**。数组要获得「近乎一等的观感」，core 至少要补两张网：

- **算术接口**：`+ - * /` 探测它；
- **归约**：`sum` / `max` / `min` / `product` 从「只认 Cons」改成「Cons 或 Indexable」。

这一条不解决，本仓的里程碑 2 无法完成。

### 4.3 缺口 3：core 没有复数

`LispValue` 的 16 个变体里没有复数，全仓搜不到 `Complex`。

平台文档模块 2 写了 `Complex128`，但 `(real z)` / `(imag z)` / `(conj z)` / `(angle z)`
要跨回 Lisp 层，就绕不开「core 有没有复数标量」的决定。

**决定：第一版 dtype 只做 `Int64` / `Float64` / `Bool`，不做复数。**
复数牵扯 `LispValue` 加变体（~24 处 match 的破坏面），等真有需求再议。

## 5. 路线图

每阶段给出**目标 / 内容 / 前置 / 验收 / 明确不做**。验收必须可测，否则不是验收。

### 阶段 1：地基（✅ 已完成 2026-11-19，随 0.1.0 发布）

**目标**：数组能被创建、观察、切片，且切片是零拷贝视图。

| 内容 | 说明 | 落点 |
|---|---|---|
| `NDArray` 表示 | dtype（Int64 / Float64 / Bool）、shape、strides、共享缓冲 | `ndarray.cj` |
| 构造 | 嵌套列表（`[[1 2] [3 4]]`）、`zeros` / `ones` / `arange` | `convert.cj` / `views.cj` |
| 形状操作 | `reshape`（含 `-1` 推断）/ `transpose` / `shape` | `views.cj` |
| 视图 | `slice`（沿第 0 维，零拷贝） | `views.cj` |
| 观察 | `display`（截断）/ `type-of` / `length` / `nth` | `ndarray.cj` |

**符号**（9 个，全部 `cangjie::` 命名空间）：
`array` / `zeros` / `ones` / `arange` / `shape` / `reshape` / `transpose` / `slice` / `ndarray?`

**前置**：无（全部在本仓内 + core 已有的 `External` 接口）。

**验收**（39 个用例，25 白盒 + 14 契约三后端差分）：
- ✅ `(cangjie::shape (cangjie::zeros 2 3))` → `(2 3)`
- ✅ `(length arr)` → 总元素数；`(nth arr i)` 按行优先扁平取值
- ✅ 修改原数组缓冲，切片视图立刻看到（零拷贝，白盒验证）
- ✅ `reshape` / `transpose` 共享缓冲；非连续数组 `reshape` 先连续化
- ✅ 2000 元素的显示被截断（不打印全部）
- ✅ 六类错误都归为 `TypeError`

**实现时踩到的坑**（已补用例钉住）：
- `arange` 的计数不能直接对 `span/step` 取整：`1.0/0.1` 在浮点下是
  `10.000000000000002`，`ceil` 会得到 11；而 `0.9999999999999999` 又少一个。
  做法是先判断商离整数有多近（容差 1e-9），近就取整，否则才向上取整。
  `arange(0, 1, 0.1)` 少一个元素会让后续统计全部错位。
- 显示浮点不能直接用 `Float64.toString()`（固定 6 位小数，`2.5` → `"2.500000"`），
  要去尾 0 并对整值补 `.0`。这与 `json-dump` 用 `.17g` 保真是**故意不同**的：
  那个是为了数据往返不失真，这个是给人看的。

**不做**：任何算术、任何广播、任何数学函数。

---

### 阶段 2：统一标量与向量

**目标**：`(sin 1.0)` 与 `(sin arr)` 同名可用；`(+ arr arr)` 按广播规则工作。

**内容**：
- **xisp 侧**（阻塞项）：core 补标量数学（§4.1）+ 算术接口与归约分派（§4.2），发新版
- 本仓：逐元素算术、广播、逐元素数学（经能力接口，不重复实现）

**前置**：xisp 新版发布到中心仓。

**验收**：
- 广播规则与 NumPy 一致，逐条覆盖：同形、标量、`[3,1] + [1,4]`、形状不兼容报错
- `(sin arr)` 与逐元素 `map` 的结果完全一致
- `(+ arr arr)` 走能力接口而非拷贝回 Lisp 列表
- 三个后端（AST / 字节码 / JIT）结果一致

**不做**：复数、`einsum` 之类的花式索引。

---

### 阶段 3：真实数据闭环

**目标**：读一份真实 CSV，做出描述统计并输出结果。

**内容**：`xisp_io`（CSV 读写）+ `xisp_stats`（描述统计、分位数、直方图、相关协方差）

**前置**：阶段 1、2。

**验收**：
- 读一个含表头、缺失值、引号转义的 CSV，字段类型推断正确
- `(mean col)` / `(std col)` 与 NumPy 同数据结果在浮点容差内一致
- 写出 CSV 后能再读回，且值不变（往返一致）

**不做**：假设检验、回归、Excel（Excel 依赖重，单独评估）。

---

### 阶段 4：线性代数

**目标**：常见矩阵运算可用，答案正确。

**内容**：`matmul` / `solve` / `det` / `inv` / `transpose` / `trace` / `rank` /
`qr` / `lu` / `cholesky`；`eig` / `svd` 视难度单独排。

**前置**：阶段 2（矩阵乘法要广播与归约）。

**决策点**：纯仓颉 vs C 后端（BLAS / LAPACK）。见 §6 S4。

**验收**：
- 已知矩阵的数值答案与参考实现一致（含条件数大的病态矩阵，不能只测良态的）
- 奇异矩阵 `inv` 报错而非返回垃圾值
- C 后端若引入，`NATIVE_ALLOWED` 登记 + CI 装上对应库

**不做**：稀疏矩阵（单独评估，它需要不同的数据结构），矩阵函数 `expm` / `sqrtm`。

---

### 阶段 5：信号处理与数值方法

**目标**：FFT、卷积、滤波、插值、拟合、优化、ODE 可用。

**内容**：`xisp_signal`（fft / ifft / conv / filter / 窗函数）+ `xisp_num`（插值、拟合、优化、ODE、积分）

**前置**：阶段 2、4（部分数值方法要用线代）。

**验收**：
- FFT 与朴素 DFT 在随机输入上逐点一致（不是只看峰值）
- 长度非 2 的幂时结果仍正确（Bluestein 或等价方案）
- ODE 求解器在已知解析解的方程上收敛阶符合理论

**不做**：自适应多步、刚性求解器（等真实需求）。

---

### 阶段 6：门面与发布

**目标**：`xisp_sci` 聚合，用户一次装齐。

**内容**：`xisp_sci` 门面（re-export + 跨域工作流）；全族发布与文档。

**前置**：前面所有阶段。**门面最后加** —— 前面没内容时，聚合一个空壳没意义。

**验收**：
- 只装 `withSci()` 就能用全部族能力，且符号不与 core 冲突（装载时检出）
- 文档站覆盖每个符号

## 6. 待决问题

| # | 问题 | 现状 / 倾向 |
|---|---|---|
| S2 | 数组是否要 core 专用 `Array` 变体（A 只加 `External` / B 加变体 / C 实现进 core） | 沿用 xisp 仓分族文档的结论：**C 明确不推荐**；A 与 B 判据是「JIT 是否为数组特化」。当前倾向 **A**，因为阶段 1 完全不需要变体 |
| S3 | 仓库 / workspace 划分 | **已定：独立仓 + 独立 workspace**（即本仓） |
| S4 | `linalg` / `signal` 的性能后端：纯仓颉 / 独立加速模块 / 同模块运行时探测 | 倾向 **先纯仓颉**。cjpm 没有可选依赖，三选一里只有「纯仓颉」不破坏零依赖假设 |
| S5 | 符号命名策略：命名空间还是前缀 | **✅ 已定（阶段 1）：`cangjie::` 命名空间前缀**。与 `cangjie::json-get` / `cangjie::http-get` / `cangjie::httpd-listen` 一致；`shape` / `slice` / `transform` 这类通用名与 core 的碰撞风险是实打实的。宿主若想要裸名，在 Lisp 层 `(define shape cangjie::shape)` 即可 —— 别名该由使用方定义，不该由库抢注 |
| **S8** | 默认布局：行优先（C 序）还是列优先（Fortran/BLAS 序） | **✅ 已定（阶段 1）：行优先**。`[[1 2] [3 4]]` 的字面量直觉就是行优先，用户心智更接近 NumPy；与 BLAS 对接时在 `linalg` 层转置。strides 通用化后这只是默认值的选择，不是能力限制 |
| **S9** | `xisp_io` 与 `xisp_json` 的关系 | 倾向**复用不重写**：JSON 已有独立仓 `xisp_json`，`io` 只做 CSV / 二进制，JSON 通过依赖它而不是自己实现 |
| **S10** | 数组字面量：要不要让 `[...]` 直接产生 ndarray | **倾向不改**。`[...]` 在 xisp 里展开成 `(cangjie::vector ...)` → 列表，是既有契约；装一个域就改变语言字面量的含义，会让所有既有 `[...]` 代码变行为。要数组就显式写 `(cangjie::array [...])` |

## 7. 与其它仓的关系

| 仓 | 关系 |
|---|---|
| `xisp` | 唯一的上游依赖。本仓用它的 `External` 协议、域装配、`InterpreterOption` |
| `xisp_json` | 数据交换格式复用，不重复实现 |
| `atelier` | 上层 AI 编排，会调用本仓能力；本仓不知道 atelier 存在 |
| `cjxt` / 前端 | 渲染本仓输出的结构化结果（图表描述、统计数据）；本仓不渲染 |
| `tsdb` / `badger-storm` | 数据持久化；本仓不存 |
