# 线性代数

`xisp_linalg`，9 个符号，**纯仓颉实现，零外部依赖**。

## 为什么不接 BLAS

`cjpm` 没有可选依赖。接 BLAS / LAPACK 意味着**每个**想用这个模块的宿主都得装 C 工具链，
这与「纯仓颉、零依赖」的前提直接冲突，而后者是这套库能被轻松嵌入的前提。

代价是慢：`matmul` 1000×1000 约 1 秒 / 2 GFLOPS，对比 OpenBLAS 单核（50~100 GFLOPS）
差 25~50 倍。但对 n < 1000 的数据分析场景够用。

真需要性能时应该**另开加速模块**（`xisp_linalg_native` 之类），不要把 C 依赖塞进本模块。

## 矩阵乘法

```lisp
(cangjie::matmul A B)
```

| A | B | 结果 |
|---|---|---|
| `2D (m,k)` | `2D (k,n)` | `2D (m,n)` |
| `1D (k)` | `2D (k,n)` | `1D (n)` —— 行向量 |
| `2D (m,k)` | `1D (k)` | `1D (m)` —— 列向量 |
| `1D (k)` | `1D (k)` | **标量**（点积） |

一维数组在 A 位置当行向量、B 位置当列向量，与 `y = A x` 的书写顺序一致。

实现上先转置 B 再点积：直接写三重循环会让 B 的访问跨行跳跃，转置后两个操作数在
内层循环里都是连续的。

## 解方程

```lisp
(cangjie::solve A b)        ; 解 A x = b
(cangjie::solve A B)        ; B 是 n×m 时，一次解 m 个方程组（共用一份 LU）
```

**部分主元不是可选项**。`[[0,1],[1,0]]` 第一步主元就是 0，不选主元直接除零；
`[[1e-20,1],[1,1]]` 这类矩阵会灾难性放大误差。

## 分解

```lisp
(cangjie::lu A)        ; → {"l": …, "u": …, "p": …}，满足 P A = L U
(cangjie::qr A)        ; → {"q": …, "r": …}，满足 Q R = A
(cangjie::cholesky A)  ; → L，满足 A = L Lᵀ（要求对称正定）
```

`lu` 返回的 `p` 是**累积后的最终置换**（1-based：`p[i]` 表示 `PA` 的第 i 行来自原矩阵的
第 `p[i]` 行）。注意它不是 LAPACK 那种「每步与谁交换」的中间量。直接拿中间量当置换会得到
非法矩阵。

`cholesky` 比 LU 快一倍且不需要选主元（对称正定保证主元恒正），有对称正定结构时优先用它。

`qr` 用 **Householder 反射**而不是 Gram-Schmidt：古典 Gram-Schmidt 在近乎线性相关的
列上会严重丢失正交性。

## 行列式与迹

```lisp
(cangjie::det A)
(cangjie::trace A)
```

`det` 用 LU 分解算，不按定义展开，因为按定义是 O(n!)。

## 奇异一律报错

`inv` / `solve` / `lu` 在矩阵奇异或接近奇异时**抛错**，不返回垃圾值。

判据是**相对容差**（乘以矩阵元素的最大绝对值），不写死绝对阈值。

一个「看起来像逆矩阵」的东西被下游继续用，比一次明确的报错危险得多。

## 病态矩阵的精度

Hilbert 矩阵 `H[i][j] = 1/(i+j+1)` 是标准压力测试，条件数随阶数指数增长：

| n | `H × H⁻¹` 偏离单位阵 |
|---|---|
| 2~8 | < 1e-6 |
| 9 | 4e-6 |
| 10 | 7.6e-5 |

前 5 阶误差 < 1e-6 是硬指标（算法有 bug 会立刻红）。9/10 阶的上升是条件数从 1e4
涨到 1e13 的必然结果，不是 bug。这时正确做法是不用 `inv`，改用 `solve` 或
正则化。

## 奇异值分解

```lisp
(define r (cangjie::svd A))
;; → {"u": m×k, "s": k, "vt": k×n}，k = min(m, n)

(hashmap-get r "s")     ; 奇异值，降序
```

`A = u · diag(s) · vt` 直接成立。它是**瘦分解** —— `u` 只有 `k` 列，够用且省内存。

SVD 是所有矩阵分解里最稳的一个：对任意形状（方阵、长方阵、秩亏）都有定义，
而且不需要矩阵有任何特殊结构。

## 秩与条件数

```lisp
(cangjie::rank A)    ; → 数值秩（整数）
(cangjie::cond A)    ; → σmax / σmin
```

**`cond` 比 `det` 可靠得多**。判断矩阵是否接近奇异时，用 `det` 接近 0 来推测是个常见错误：
`det(A)` 是**所有**奇异值的乘积，维度一高就既会溢出也会下溢 —— 一个 20×20 的矩阵，
即使每个奇异值都是 2，`det` 也是 100 万；而其中只要有一个是 1e-10，`det` 就掉到 1e-4，
看起来「快奇异了」，实际上另外 19 个方向都好好的。

条件数直接回答「解对输入扰动有多敏感」：

| `cond` | 含义 |
|---|---|
| ≈ 1 | 完美条件（正交矩阵） |
| 1e1 ~ 1e6 | 正常，float64 有约 16 位有效数字，够用 |
| 1e8 ~ 1e12 | 勉强，结果大约只有 16 − log₁₀(cond) 位可信 |
| > 1e15 | 数值上等同于奇异 |
| `inf` | 严格奇异 |

## 伪逆

```lisp
(cangjie::ginv A)    ; → n×m 的 Moore-Penrose 伪逆
```

`inv` 对奇异矩阵只能报错，**`ginv` 永远有定义** —— 奇异矩阵、长方阵都有。

伪逆最重要的性质是 `A · A⁺ · A = A`。当 `A` 满秩方阵时它等于 `inv(A)`；
当方程组无解（超定）时，`A⁺y` 就是最小二乘解，与 `lstsq` 给出同一个答案。

## 特征分解

```lisp
(cangjie::eigen S)
;; → {"values": n（降序）, "vectors": n×n}
```

**只接受对称矩阵。** 非对称矩阵的特征值可能是复数，而本仓的 dtype 只有
`Int64` / `Float64` / `Bool`，没有复数。硬做就得返回「实部 + 虚部」两套数组，
那是半吊子方案。

报错比给出错答案好：把非对称矩阵当对称矩阵算，会得到一个**看起来正常、实际毫无意义**的
结果 —— 你没有任何理由怀疑它。

任意矩阵请用 `cangjie::svd`，它对所有矩阵都有定义。

统计里真正需要特征分解的东西（协方差矩阵、相关矩阵）全都是对称的，所以这个限制
实际不构成障碍。

## 主成分分析

```lisp
(define p (cangjie::pca X))        ; X 是 n×p，每行一个样本
;; → {"scores": n×k, "loadings": p×k, "sdev": k,
;;    "var-explained": k, "center": p}

(cangjie::pca X 2)                 ; 只要前两个主成分
```

**`var-explained` 回答「这个主成分有多重要」**：

```lisp
(define ve (hashmap-get p "var-explained"))
;; → 例如 [0.963 0.037]：第一个主成分吃掉 96.3% 的方差
```

`loadings` 的每一列是一个主成分，也就是原始变量上的权重 —— 用它判断「这个主成分
主要反映哪些变量」。

### 为什么用 SVD 而不是协方差矩阵的特征分解

教科书讲 PCA 都从「对协方差矩阵做特征分解」入手。但那样要先算 `XᵀX`，
而这一步把**条件数平方**：`cond(XᵀX) = cond(X)²`。数据本身条件数 1e8 时，
协方差矩阵已经是 1e16 —— 超出 float64 能表示的精度，后面算什么都白搭。

直接对中心化后的 `X` 做 SVD 就绕开这一步。本仓的 `pca` 走的是这条路。
