# xisp_linalg

星枢科学计算线性代数：矩阵乘法、LU / QR / Cholesky 分解、SVD / 特征分解、解方程求逆、以及建在它们上面的秩 / 条件数 / 伪逆 / PCA。

**纯仓颉实现，零外部依赖** —— 不接 BLAS / LAPACK。`cjpm` 没有可选依赖，接 C 库意味着
每个用本模块的宿主都得装 C 工具链，与 `xisp_array` 一直守着的零依赖前提冲突。

```lisp
(cangjie::matmul A B)                        ; 矩阵乘法（含向量 / 点积）
(cangjie::det A)                             ; 行列式
(cangjie::solve A b)                         ; 解 A x = b
(cangjie::inv A)                             ; 逆矩阵
(cangjie::trace A)                           ; 迹
(cangjie::cholesky A)                        ; 对称正定 → L（A = L Lᵀ）
(cangjie::lu A)                              ; {"l": …, "u": …, "p": …}（P A = L U）
(cangjie::qr A)                              ; {"q": …, "r": …}（Q R = A）
(cangjie::lstsq X y)                         ; 最小二乘，多元线性回归的地基
(cangjie::svd A)                             ; {"u": …, "s": …, "vt": …}（A = U Σ Vᵀ）
(cangjie::eigen A)                           ; {"values": …, "vectors": …}（对称矩阵）
(cangjie::rank A)                            ; 数值秩
(cangjie::cond A)                            ; 2-范数条件数
(cangjie::ginv A)                            ; Moore-Penrose 伪逆
(cangjie::pca X)                             ; 主成分分析
```

## `matmul` 的维度组合

一维数组在 **A 位置当行向量、B 位置当列向量**（与 `y = A x` 的书写顺序一致）：

| A | B | 结果 |
|---|---|---|
| `2D (m,k)` | `2D (k,n)` | `2D (m,n)` |
| `1D (k)` | `2D (k,n)` | `1D (n)` |
| `2D (m,k)` | `1D (k)` | `1D (m)` |
| `1D (k)` | `1D (k)` | **标量**（点积） |

## 奇异值分解与特征分解

```lisp
(cangjie::svd A)      ; → {"u": m×k, "s": k（降序）, "vt": k×n}，k = min(m,n)
(cangjie::eigen S)    ; → {"values": n（降序）, "vectors": n×n}
```

`svd` 给的是**瘦分解**：`u` 是 `m×k`、`vt` 是 `k×n`，`k = min(m,n)`。
`A = u · diag(s) · vt` 直接成立，不用自己拼。

### 为什么用 Jacobi 而不是 Golub-Kahan-Reinsch

GKR 更快，但要 Householder 双对角化 + 隐式 QR 带 Wilkinson 位移，几百行且每步都得仔细验。
Jacobi 赢在**精度**：它给出的每个奇异值都有高**相对**精度，而 QR 路线的小奇异值相对误差会
退化 —— 而 `cond`（σmax/σmin）和 `rank`（数有几个 σ 显著大于 0）恰恰完全依赖小奇异值。
用 GKR 的结果算条件数，会在最需要它的时候给出不准的数。

慢一点无所谓：数据分析的矩阵（n < 1000）用不上那点速度差。

### `eigen` 只接受对称矩阵

非对称矩阵的特征值**可以是复数**，而本仓的 dtype 只有 `Int64` / `Float64` / `Bool`
（路线图 §4.3 明确决定不做复数）。硬做就得返回「实部数组 + 虚部数组」，
那等于在没有复数类型的前提下发明一套半吊子的表示。

所以 `eigen` 对非对称矩阵**报错并提示改用 `svd`**（后者对任意矩阵都有定义）。

**不检查才危险**：非对称矩阵被当成对称矩阵算，会给出一个「看起来正常、实际毫无意义」的结果——
Jacobi 迭代会把下三角折到上三角里，得到的「特征值」既不是原矩阵的也不是任何东西的。

统计场景里真正需要特征分解的（协方差矩阵、相关矩阵、PCA）全都是对称的，所以这个限制
在实践中几乎不构成障碍。

### 秩与伪逆的阈值

`rank` 和 `ginv` 都要判断「这个奇异值算不算 0」。**绝对阈值没有意义**：把整个矩阵乘 1e-6 后，
所有奇异值都小于 1e-3，但秩没变。所以用相对判据：

```
σ > max(m, n) · ε · σmax        （ε = 2.22e-16，float64 机器精度）
```

与 NumPy `matrix_rank` 的默认约定一致。含义是「相对最大奇异值而言，这个 σ 已经小到舍入误差的量级」。

`cond` 对严格奇异矩阵返回 `inf`，对全零矩阵返回 `0`（秩 0，谈不上病态）。

### `pca` 用 SVD，不用协方差矩阵的特征分解

教科书讲 PCA 都是从「对协方差矩阵做特征分解」入手，但那样要先算 `XᵀX` ——
而这一步把条件数**平方**（`cond(XᵀX) = cond(X)²`）。数据本身条件数 1e8 时，
协方差矩阵已经是 1e16，超出 float64 的精度了。

直接对中心化后的 `X` 做 SVD 就避开了这个问题：

```lisp
(cangjie::pca X)      ; → {"scores": n×k, "loadings": p×k, "sdev": k,
                      ;    "var-explained": k, "center": p}
(cangjie::pca X 2)    ; 只要前两个主成分
```

`sdev = Σ/√(n−1)`、`var-explained = σ²/Σσ²`。`loadings` 的每一列是一个主成分
（即原始变量上的权重），`scores` 是数据在该主成分上的坐标。

## 设计要点

**一律按 Float64 计算**，Int 数组自动提升。

**部分主元不是可选项**。`[[0,1],[1,0]]` 第一步主元就是 0，不选主元会直接除零；
`[[1e-20,1],[1,1]]` 这类矩阵会得到灾难性的误差放大。

**奇异 / 非正定 / 非对称一律报错**，不返回垃圾值 —— 一个"看起来像逆矩阵"的东西被下游
继续用，比一次明确的报错危险得多。奇异判定用**相对容差**（乘以矩阵元素最大绝对值），
不写死绝对阈值。

**`lu` 返回的 `p` 是累积后的最终置换**（1-based：`p[i]` 表示 `PA` 的第 i 行来自原矩阵的
第 `p[i]` 行），满足 `P A = L U`。注意它不是 LAPACK 那种"每步与谁交换"的中间量 ——
直接拿中间量当置换会得到非法矩阵。

**Cholesky 比 LU 快一倍且不需要选主元**（对称正定保证主元恒正），所以有对称正定结构时
优先用它。

**QR 用 Householder 反射**，不是 Gram-Schmidt —— 古典 Gram-Schmidt 在近乎线性相关的列上
会严重丢失正交性。

**`lstsq` 走 QR 而不是正规方程**。正规方程把条件数平方（`cond(XᵀX) = cond(X)²`），
一个条件数 1e6 的设计矩阵直接变成 1e12，多精度就全丢了。QR 只把 `Qᵀy` 的前 n 个分量
回代，不显式求逆。

秩亏（特征线性相关）时**报错**而不是给出某个"解" —— 系数不唯一时静默返回一个答案，
会让用户以为找到了唯一答案。
